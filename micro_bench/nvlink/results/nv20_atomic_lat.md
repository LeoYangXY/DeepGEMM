### nv20_atomic_lat — 远端原子的完整往返是 1705 cyc (861 ns)，但无返回值的 `red` 是完全 posted 的，发射只要 46 cyc

**假设**

跨 NVLink 的原子操作，如果需要返回旧值，就必须等一个完整的跨卡往返；如果不需要返回值（PTX `red.*`），理论上可以 fire-and-forget，发出去就不管了。若成立，`atom` 与 `red` 的延迟差就等于「等返回值的往返代价」。此外 `.sys` scope 相比 `.gpu` 是否要额外付出代价（绕过缓存 / 隐含 fence）也需要验证。

**方法**

单线程 `<<<1,1>>>`，循环 NITER=2000 次原子，用 `clock64()`（SM 时钟域 1.980 GHz）测总周期后除以 NITER。

关键在于**强制串行**：必须让上一次原子的返回值真正参与下一次原子的地址计算，否则测出来的是发射间隔而不是延迟。第一版用 `dep = r & 0` 被 ptxas 常量折叠了，结果本地和远端完全相同（都是 46 cyc），依赖链断裂。改用一条不透明的 inline PTX：

```c
__device__ __forceinline__ unsigned opaque_zero(unsigned r, unsigned mask) {
  unsigned o;
  asm volatile("and.b32 %0, %1, %2;" : "=r"(o) : "r"(r), "r"(mask));
  return o;
}
```

`mask` 是运行时传入的 0，编译器无法折叠 inline asm 的输出，于是得到一个恒为 0 但硬件必须等返回值才能算出的地址偏移量。修正后本地/远端立刻分开（531 vs 1705），证明依赖链生效了。

`red.*` 没有返回值，无法构造依赖链，所以它那一栏测的是**发射间隔**而非完成延迟。为了另外拿到完成延迟，额外跑了 `red + membar.sys` 的版本。

**结论**

1. **远端原子的完整往返 = 1705 cyc = 861 ns，本地 = 531 cyc = 268 ns，净跨卡代价 = 1174 cyc = 593 ns。** 依据 A 段 `atom.gpu.add.u32` 行。这 593 ns 与 nv34 测出的 NVLink+NVSwitch 净往返 656 ns、以及本文件 E 段 `ld.volatile` 的远端-本地差 (1635-289=1346 cyc) 属同一量级，但原子的净差比纯读的净差**小** 172 cyc，说明原子请求不需要像读那样把整条 line 搬回来。

2. **写类原子在 NVLink 上是完全 posted 的。** 依据 D 段：`red.gpu.add.u32` 本地 46.0 / 远端 46.1 cyc，**远/本 = 1.00**，远端和本地一模一样。发射一次远端原子只要 46 cyc（23 ns），完全看不到 861 ns 的往返。对比同一行的 `atom` 版本 1705 cyc —— **`atom` - `red` = 1659 cyc = 838 ns 就是「等返回值」的纯代价，占 `atom` 总延迟的 97%。** 即：远端原子的开销几乎全部来自等返回值，而不是做原子本身。

3. **46 cyc 是原子指令的发射间隔（issue interval），不是完成延迟。** 依据 E 段：加上 `membar.sys` 后 `red` 远端变成 1758.9 cyc，与 `atom` 的 1705 cyc 接近（略高 54 cyc，是 fence 本身的开销）。这说明 `red` 那 46 cyc 只是把请求塞进队列的时间，真正完成仍需 ~1700 cyc，只是线程不必等它。

4. **op 类型和数据宽度对延迟完全没有影响。** A 段 5 种操作 (add/exch/cas/min/and) 远端全部落在 1704.3–1706.7 cyc，极差 2.4 cyc (0.14%)；C 段 u32/u64/f32/f64 全部落在 1705.1–1706.9 cyc。**延迟 100% 由链路往返决定，与 L2 里做什么运算、做多宽无关**，说明 L2 的原子 ALU 相对链路延迟可以忽略（<3 cyc）。这也意味着跨卡场景下用 64-bit 原子不比 32-bit 贵。

5. **`.sys` scope 相对 `.gpu` 零额外代价。** `atom.sys.add.u32` 远端 1705.9 vs `atom.gpu.add.u32` 1705.2，差 0.7 cyc。连 `release`/`acquire` 语义版本也一样（1706.4 / 1707.1）。**在已经跨卡的路径上，scope 修饰符不产生额外可测开销** —— 因为远端访问本来就绕过了本地 L2，`.sys` 要求的那些效果是免费附带的。这条对写跨 GPU 同步代码是好消息：直接用 `.sys` 不要省。

6. **纯读 (1635 cyc) 比原子往返 (1705 cyc) 便宜 70 cyc = 35 ns**，这 70 cyc 可以理解为远端 L2 执行 RMW 并串行化的额外成本。

**不确定性**

- `red` 的 46 cyc 发射间隔是在单线程、连续发射、无背压的条件下测的。一旦队列填满（多线程高压场景），发射间隔会被反压拉长到实际服务速率 —— nv21 测到的满载值是每次 L2 原子 86.8 ns，与这里的 23 ns 不矛盾（那是多线程竞争同一地址后的串行化速率）。
- 本地 531 cyc 明显高于典型的 L2 命中 ~290 cyc（见 E 段 `ld.volatile` 本地 288.7）。原因是原子强制绕过 L1 且要走 L2 的原子单元排队，531 - 289 = 242 cyc 是本地原子相对本地读的额外成本。
- 所有数字取 5 次重复中的最小值（去掉第一次预热），run-to-run 抖动 <0.5%。
