### nv34_remote_tlb — 远端访问的地址翻译代价，以及 peer 内存进哪一级缓存

**假设**：GPU0 读 GPU1 的一次访问，地址要经过「本地判定这块在 peer 上」+「到 GPU1 后定位物理页」两层。peer 地址翻译有多少 TLB entry、peer 映射有几个槽位，官方零资料。

**方法**：
- A 段：2 MB 步长的指针追逐，页数 N 从 1 扫到 8192（覆盖 2 MB → 16 GB）。页序做伪随机置换破坏预取。同时跑两种 load：普通 `ld`（可命中 L1/L2）和 `ld.global.cv`（强制绕过缓存）。**两条曲线相减就能把「缓存效应」和「TLB 效应」分开**——bypass 曲线上的台阶才是 TLB。
- B 段：在 GPU1 上做 K 块**独立的** `cudaMalloc`（每块 2 MB），GPU0 用一个跨 buffer 的串行指针环轮流访问。串行是关键：每块 buffer 首元素存「下一块的编号」，保证下一次访问的地址依赖上一次读回的值，测的才是延迟而不是吞吐。
- C 段：远端写带宽，1 块连续 1 GB vs K 块打散的 2 MB。每个 block 整块负责一段以保持完美合并，这样差异只可能来自映射被打散。

**实测数据**

A) 页数扫描（cycles @ 1.98 GHz）：

| 页数 N | 覆盖 | 本地 cached | 远端 cached | 本地 bypass | 远端 bypass |
|---|---|---|---|---|---|
| 1 | 2 MB | 41 | **41** | 297 | 1616 |
| 8 | 16 MB | 41 | 41 | 282 | 1589 |
| 64 | 128 MB | 41 | 41 | 284 | 1587 |
| 256 | 512 MB | 41 | 41 | 289 | 1586 |
| 1024 | 2.0 GB | 41 | **41** | 291 | 1603 |
| 2048 | 4.0 GB | 167 | 1120 | 292 | 1606 |
| 4096 | 8.0 GB | 293 | **1608** | 293 | 1608 |
| 8192 | 16.0 GB | 294 | 1610 | 294 | 1610 |

B) peer 独立分配数量扫描：

| K（独立 2MB 分配数） | 覆盖 | 串行远端延迟 cyc |
|---|---|---|
| 1 | 2 MB | 1559 |
| 8 | 16 MB | 1614 |
| 64 | 128 MB | 1612 |
| 256 | 512 MB | 1614 |
| 1024 | 2048 MB | 1615 |

C) 打散映射对远端写带宽的影响：

| 布局 | GB/s |
|---|---|
| 1 块连续 1 GB | 370.8 |
| 8 块独立 2 MB | 351.3 |
| 32 块独立 2 MB | 340.5 |
| 128 块独立 2 MB | 305.1 |
| 512 块独立 2 MB | 371.1 |

**结论**

1. **peer 内存会进本地 L1，但不进本地 L2**。这是本实验最重要的发现，证据是 A 段两列的交叉对比：
   - N ≤ 1024（working set = 1024 条 line = 128 KB）时，远端 cached = **41 cyc**，和本地 L1 命中一模一样 → peer 数据确实躺在 GPU0 的 L1 里。
   - N = 4096（working set = 512 KB，远远塞得进 60 MB 的 L2）时，远端 cached = 1608，与远端 bypass 的 1608 **完全相等** → L2 一次都没命中。作为对照，本地在同样 N 下 cached = 293 = L2 命中延迟。
   
   也就是说 NVLink peer 内存的可缓存层级只到 L1（256 KB/SM），L2 对它完全透明。这条决定了跨卡访问的复用窗口只有 L1 那么大。

2. **L1 有效容量 ≈ 128–256 KB**。N=1024（128 KB）全命中 41 cyc；N=2048（256 KB）开始失效。按 `h·41+(1-h)·293 = 167` 解出本地命中率 50%，符合 H20 的 256 KB L1 在随机访问下的抖动行为。

3. **远端访问的 TLB reach ≥ 16 GB，量程内看不到任何台阶**。远端 bypass 列从 N=1 到 N=8192 一路平在 1586–1616 cyc，波动 ±2%，**没有台阶**。用 2 MB 页时 8192 页 = 16 GB 覆盖仍不产生翻译缺失。所以「远端访问要多交一份地址翻译税」在这个量程上不成立。

4. **远端 uncached 往返延迟 = 1590 ± 20 cyc = 803 ns**，本地 L2 命中 = 290 cyc = 146 ns。**远端比本地 L2 贵 5.5×，绝对差 1300 cyc = 656 ns**，这 656 ns 就是 NVLink + NVSwitch 的净往返代价。

5. **peer 映射槽位在 1024 块独立分配内不会耗尽**。B 段从 K=1 到 K=1024 延迟平在 1559–1615 cyc，无跳变。2 GB 分散在 1024 块独立 `cudaMalloc` 里，访问延迟和一块连续的没区别。

6. **打散映射对带宽基本无损**。C 段 370.8 → 305~371，且 512 块反而回到 371.1，说明中间那些下降是噪声而非结构性衰减。**跨卡访问不需要为了性能刻意做大块连续分配**（真正需要连续的是 nv32 里的 256 B 条带跨度，那是另一回事）。

**不确定性**
- A 段用的是 2 MB 页（`cudaMalloc` 的默认后备页）。没测 4 KB 小页下的 TLB reach，如果驱动在某些场景退化到小页，结论可能不同。
- 「peer 不进本地 L2」是从延迟推的。更硬的证据应该是数线上字节（反复读一个小 buffer，看 wire 上的 Rx 是不是 N 倍）——这一条交给 nv15 做计数器交叉验证。
- C 段 128 块那行的 305.1 GB/s 没有解释清楚，重复测量应该能确认它是噪声，但本次没有重复足够多次。
