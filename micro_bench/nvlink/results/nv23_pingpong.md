### nv23_pingpong — 跨 GPU 同步的硬地板：一次 flag ping-pong 往返 2671 ns（最优放置），host pinned 慢 1.66×；单线程搬 payload 只有 0.2 GB/s

**假设**

两个 GPU 用 flag 互相 ping-pong 一次的时间，是任何跨 GPU 同步原语（barrier、allreduce 的一步）的物理下界。想知道：(1) 这个下界是多少，与 nv20 的单次远端往返 861 ns 差多少；(2) flag 放在哪一侧显存最快，host pinned 是否可用；(3) 「写 payload → 置 flag → 对端看到 flag → 读 payload」的端到端延迟里，固定开销和数据传输各占多少。

**方法**

GPU0 跑 `k_ping<<<1,1>>>`，GPU1 跑 `k_pong<<<1,1>>>`，各自在自己 device 的 non-blocking stream 上。共用一对 flag：

```
ping: st.release.sys(f0, seq);  自旋等 ld.acquire.sys(f1) == seq
pong: 自旋等 ld.acquire.sys(f0) == seq;  st.release.sys(f1, seq)
```

必须用 `.sys` scope，`.gpu` scope 跨 GPU 不保证可见。ping 侧用 `clock64()` 量 N=20000 次往返总时间除以 N。

**死锁防护**（这是本实验最大风险，团队要求重点处理）：

- 每个自旋循环有 `SPIN_MAX = 2e8` 上限（~0.1 s @2 GHz），超过就置 timeout 标志并跳出所有循环，kernel 正常返回。
- 两个 kernel 各写自己的 status，主机侧回读检查，所有结果行都带「超时」列。
- launch 顺序：**先 launch pong**（消费者，会先进入自旋等），再 launch ping，然后对两个 device 都 `cudaDeviceSynchronize`。
- 先用 N=64 跑 smoke test，通过了才放大到 N=20000。
- 每次测量前 flag buffer 都 memset 归零并 sync。

实际运行 0 次超时，全部 status=0。

**实测数据**

Smoke test（N=64）：RTT = 11474.4 cyc (5795.1 ns), timeout=0 —— 小迭代数下有启动瞬态，故正式测量用 N=20000。

A) 纯 flag ping-pong RTT vs flag 放置位置（N=20000）

| flag 放置 (f0 / f1) | RTT cyc | RTT ns | 超时 |
|---|---|---|---|
| f0=GPU0, f1=GPU0（都在发起方本地） | 6251.1 | 3157.1 | 0 |
| f0=GPU1, f1=GPU1（都在对端） | 6317.5 | 3190.6 | 0 |
| **f0=GPU1, f1=GPU0（各写对端, 各读本地）** | **5288.7** | **2671.1** | 0 |
| f0=GPU0, f1=GPU1（各写本地, 各读对端） | 6242.6 | 3152.8 | 0 |
| f0=host pinned, f1=host pinned | 8758.6 | 4423.5 | 0 |

B) payload 大小 vs 端到端同步往返（N=4000，payload 在 GPU1 显存，GPU0 远端写入）

| payload B | RTT cyc | RTT ns | 增量 ns | 等效 GB/s |
|---|---|---|---|---|
| 0 | 7694.9 | 3886.3 | 0.0 | — |
| 64 | 8865.1 | 4477.3 | 591.0 | 0.1 |
| 256 | 10758.8 | 5433.7 | 1547.4 | 0.2 |
| 1024 | 17460.8 | 8818.6 | 4932.3 | 0.2 |
| 4096 | 44630.9 | 22540.8 | 18654.5 | 0.2 |
| 16384 | 162995.7 | 82321.1 | 78434.7 | 0.2 |
| 65536 | 626249.8 | 316287.8 | 312401.4 | 0.2 |

**结论**

1. **跨 GPU 同步的硬地板 = 2671 ns（5289 cyc），这是最优 flag 放置下的一次完整 ping-pong。** 依据 A 段第 3 行。对照 nv20 的单次远端原子往返 861 ns：一次 ping-pong 逻辑上是 2 个单向跨卡传播，若每个单向 ≈ 430 ns（861/2），纯传播只需 861 ns。**实测 2671 ns，多出的 1810 ns 是自旋检测开销** —— 轮询侧不是数据一到就立刻发现，而是要等当前那次 `ld.acquire.sys` 返回后再发起下一次，每次轮询本身就是一个远端读（nv20 实测 826 ns）。所以同步延迟 ≈ 2 × 传播 + 2 × 轮询粒度。

2. **最优放置是「各写对端、各读本地」，比其它 GPU 显存放置快 1.18×。** 依据 A 段：2671.1 ns vs 其余三种 3152.8 / 3157.1 / 3190.6 ns（这三种彼此只差 1.2%，基本等价）。原因是这种放置下**自旋轮询命中的是本地显存**（便宜，本地 L2 ~146 ns），只有置位是远端写（而远端写是 posted 的，不用等）。其余放置至少有一侧要远端轮询，每次轮询付 826 ns。**给 NCCL 类库的直接建议：同步 flag 应该放在读它的那一侧，写方远程写过去。**

3. **host pinned 内存做 flag 比 GPU 显存慢 1.66×（4423.5 vs 2671.1 ns）。** 依据 A 段最后一行。慢 1752 ns，说明 flag 走 PCIe 到主机内存的往返明显贵于走 NVLink 到对端显存。**在有 NVLink 的拓扑上没有任何理由把同步 flag 放 host 内存。**

4. **payload 传输和同步是完全串行叠加的，没有重叠。** 依据 B 段：增量 ns 随 payload 严格线性增长（64B→591 ns, 65536B→312401 ns，比值 1024:528，接近线性），且 payload=0 的基线 3886.3 ns 与 A 段同等放置的数值同量级。说明「写 payload → fence → 置 flag」这条路径上，`__threadfence_system()` 强制 payload 先落地，**数据传输时间和同步时间是相加而非重叠的**。

5. **单线程搬运 payload 只有 0.2 GB/s，是 370 GB/s 峰值的 1/1850。** 依据 B 段「等效 GB/s」列，从 256 B 到 64 KB 稳定在 0.2。原因是 `<<<1,1>>>` 单线程能维持的 outstanding 请求数极少（nv08 量级的 MLP 限制），完全无法填满链路。**这个数字的意义：不要用单线程 kernel 做跨 GPU 数据搬运，同步用单线程可以，搬数据必须开满线程。** 也说明 B 段测的「端到端延迟」在大 payload 时被单线程带宽主导，不代表真实流水线性能（那是 nv25 的任务）。

6. **payload 从 0 到 64 B 的边际代价是 591 ns**，接近一次单向远端写的传播时间。即**第一个字节最贵**，之后每 64 B 只加约 30 ns（从 64B 的 591 到 256B 的 1547，增 956 ns / 3 个 64B 单位）。小消息同步的成本几乎全是固定开销。

**不确定性**

- N=64 的 smoke test 得到 5795 ns，比 N=20000 的 3157 ns 高 84%，说明前几十次往返有明显启动瞬态（TLB、L2 状态、时钟爬升）。正式数据用 N=20000 摊薄，但没有单独统计尾部分布，无法给出 p99 抖动。nv18 测过 hop jitter，可交叉参考。
- 自旋轮询的粒度无法从本实验分离出来 —— 结论 1 中「1810 ns 是自旋检测开销」是用 861 ns 传播时间倒推的，属于模型推断而非直接测量。要直接测需要在轮询循环里插桩记录每次 `ld.acquire` 的耗时，未做。
- B 段的 payload 写入用的是 `st128`（16 B/次）循环，64 KB 需要 4096 次迭代，单线程的指令发射开销也计入了「增量 ns」，所以 0.2 GB/s 是「单线程写远端」的综合速率，不是纯链路速率。
- 只测了 GPU0↔GPU1 一对。平台拓扑对称（任意 GPU 对 1 hop 经 NVSwitch），预期其它对相同，但未验证。
