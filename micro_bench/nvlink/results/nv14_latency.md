### nv14_latency — 远端 NVLink 读延迟 1589 cyc，其中 1302 cyc 是纯 NVLink+NVSwitch 往返；`.cg/.lu/.cv/volatile` 会强制绕过本地缓存

**假设**
远端读延迟 ≈ 本地缓存层级查询 + NVLink/NVSwitch 往返 + 远端侧内存访问。不同 PTX cache modifier 决定请求在本地 L1/L2 上是查询-命中还是强制下推，因此可以用 modifier 作为"开关"把各段拆开。

**方法**
`<<<1,1>>>` 单线程 pointer-chase，链表是随机置换的单环，下一跳地址由上一次 load 的返回值决定 → 真串行、无法预取或重排。步长 8 KB（远大于 128 B L2 line / 32 B sector），小 WS 档用 256 B 步长以保证节点数。working set 分四档 32 KB / 8 MB / 32 MB / 512 MB，分别落在 L1 内、L1 外 L2 内、L2 容量边界、远超 60 MB L2。buffer 分别放 GPU0（本地）和 GPU1（远端），**发起端永远是 GPU0**。每档扫 8 种 modifier，每个组合 best-of-5，采样循环内不写 global，kernel 内先跑 512 次 warmup 预热 TLB 和指令流水。

控制变量：同一条链、同一段代码、同一发起端，**只改 buffer 所在 device** 和 **只改 modifier**，所以两两相减的差值可归因到单一因素。

**结论**

1. **本地层级绝对值**：L1 命中 **38.8 cyc = 19.6 ns**（表 A 行1列1）；L2 命中 **282.1 cyc = 142.5 ns**（行3列1）；HBM **287.4 cyc = 145.2 ns**（行4列1）。
2. **远端读总延迟 = 1589.2 cyc = 802.6 ns**（行8列1）。
3. **拆解**（全部取 `ld.global` 列）：
   - L1→L2 增量 **243.3 cyc (122.9 ns)** = 本地 L2 查询+返回
   - L2→HBM 增量 **仅 5.3 cyc (2.7 ns)** —— 说明 32 MB 档已经基本 miss 到 HBM，282 cyc 那一档其实主要是 HBM 延迟；真正的 L2 命中延迟应看 8 MB 档的 **69.2 cyc (35.0 ns)**（行2列1）。修正后的层级是 **L1 38.8 / L2 69.2 / HBM ~287 cyc**。
   - HBM→remote 增量 **1301.8 cyc (657.5 ns)** = NVLink+NVSwitch 往返净开销
4. **modifier 的作用是二值的，不是渐进的**：`.cg` / `.lu` / `.cv` / `volatile` 四者在远端 32 KB WS 下全部是 ~1580 cyc，而 `ld.global` / `.ca` / `.cs` / `.nc` 全部是 38.8 cyc，**差 1542 cyc**（表 D 行5）。这四个 modifier 强制请求下推、绕过本地缓存；另四个允许本地缓存命中。
5. **关键推论：peer 内存会被本地 L1/L2 缓存。** 远端 32 KB WS 用 `ld.global` 只要 38.8 cyc —— 与本地 L1 命中完全相同（38.8）。若远端内存不可缓存，这里不可能低于 1580 cyc。这一条由 nv15 的硬件计数器独立证实。
6. `.cs`（streaming）在大 WS 下略快：远端 32 MB 档 1535.0 vs 1582.9，**省 47.9 cyc**（表 D 行7），因为它不做 LRU 插入、省了一次替换决策。

**不确定性**
- 空循环基线被编译器优化为 0，因此各档数字含少量循环/地址计算开销（由 nv18 测得 `clk()` 背靠背为 7 cyc，量级可忽略但未逐项扣除）。
- 「local L2 (32 MB)」档 282 cyc 与 HBM 287 cyc 几乎相同，说明 32 MB 并没有稳定驻留在 60 MB L2 中（存在其他 CTA/驱动占用与随机步长导致的 set 冲突），所以本文用 8 MB 档代表 L2 命中。
- 8 MB 远端档 231.8 cyc 是"部分命中本地 L2"的混合态，不代表任何单一层级。
