### nv10_sm_scale — 远端写在 6 个 SM 前完美线性、16 个 SM 饱和于 373 GB/s，且过饱和 19 倍无拥塞崩溃

**假设**
如果 NVLink 的瓶颈在 **link 侧**（有限的线路带宽），带宽曲线会随 SM 数线性上升到某个
平台后**平坦**；如果瓶颈在 **SM 侧**（每 SM 一个小出口），线性段的斜率就等于单 SM 出口，
且需要足够多 SM 才能撞到 link 顶。若过饱和后带宽**下降**，说明存在拥塞崩溃
（credit 抖动 / 队列颠簸）。这三种形态可以互相区分。

**方法**
- `__launch_bounds__(256,1)` + block=256，grid 从 1 细扫到 312（=78×4，覆盖 4 个 wave）。
- 固定总流量 256 MB，grid-stride，`st128`。`bench_ms(...,3)` best-of-3。
- 同时跑远端写 / 远端读 / 本地写三条曲线做形态对照。
- 对照实验：block=1024（32 warp/SM，占满 SM）跑同样的 grid，检验"少 SM 多 warp"
  能否换来更多带宽 —— 这是区分"SM 数不够"和"每 SM 出口有限"的判决性实验。
- NVLink 硬件字节计数器交叉验证，确认流量确实走了 link 且字节数对得上。

**结论**

1. **单 SM 出口 = 50.5 GB/s，跨 6 个 SM 保持严格线性。** 依据：grid=1..6 的
   remWR/SM 列为 50.64 / 50.60 / 50.56 / 50.54 / 50.42，**离散度 0.4%**。
   这独立复现了 nv09 的 50.4 GB/s。
2. **饱和点：grid=16，373.48 GB/s。** 依据：峰值行。grid=6 已达 81.8%，
   grid=10 达 95.2%，grid=16 之后 remWR 不再增长（grid 32→312 全在 368~371）。
   **饱和 NVLink 写只需要 16/78 = 20.5% 的 SM。**
3. **瓶颈在 link 侧，不在 SM 侧 —— 由 block=1024 对照判决。** 依据：对照表
   `vs blk256` 列在 grid=1/4/8 全是 **1.00x**。把每 SM 的 warp 数从 8 提到 32（4 倍），
   带宽一点不变（50.45 vs 50.64、202.17 vs 202.17、311.33 vs 312.90）。
   ⇒ 少 SM 时的带宽限制是**每 SM 的固定出口**（50.5 GB/s，加 warp 无用）；
   而 grid≥16 后的 373 GB/s 上限是**共享的 link 侧**限制（加 SM 也无用）。
   两个瓶颈在 grid≈7.4（=373/50.5）处交接。
4. **无拥塞崩溃。** 依据：grid 从 16 到 312（**19.5 倍过饱和**），remWR 在
   361.91（grid=39，最低）到 373.48（grid=16，最高）之间波动，极差仅 **3.1%**，
   且末端 grid=312 的 370.62 与 grid=16 的 373.48 基本持平。
   ⇒ NVLink 的流控是**基于 credit 的无损背压**，过量请求在 SM 侧排队等待而不是
   被丢弃重传，因此不会出现 TCP 式的崩溃。
5. **本地 HBM 写在 60 个 SM 才饱和于 3597 GB/s**（locWR 列 grid=60 行），
   是远端的 **9.7 倍**。远端写只用 16 个 SM 就到顶 ⇒ 远端场景下 62 个 SM 的
   访存能力是闲置的，这是 NVLink 应用的核心约束。
6. **字节计数器完全对账：dataTx/payload = 1.000**（5368.7 vs 5368.7 MB）。
   确认没有隐藏的读-改-写放大，测的就是纯远端写。
   附带观察：纯写流量下 `rawRx = 4861.9 MB`（反向 raw 流量达正向 payload 的 90.6%），
   这是 credit return / ack 的协议开销 —— 与 nv12 观测到的背压现象同源。

**不确定性**
- grid≤78 时"grid ≈ 活跃 SM 数"依赖调度器把 block 均匀铺开；occupancy 报告说
  k_wr256 可以驻留 8 block/SM，所以 `__launch_bounds__(256,1)` 只是 hint，
  并未真正强制 1 block/SM。grid<78 时调度器**通常**会先铺满不同 SM，但未用 `%smid`
  验证。若某些 grid 下 block 挤在同一 SM，会低估该点带宽 —— grid=24 的 363.87
  和 grid=39 的 361.91 这两个小凹陷可能就是这个原因。
- 373.48 GB/s 与之前基线 370 GB/s 的 0.9% 差异在 best-of-3 的噪声范围内。
- `raw/data=2.037` 的解释（协议头 + credit 回传各占多少）属于 grp-a 的 wire 效率
  议题，此处只做交叉验证不下结论。
